# เซิร์ฟเวอร์ BeamNG (BeamMP) บน Pi

แผงคุมอยู่ในเว็บ dashboard ที่แท็บ **BeamNG** — เห็นเฉพาะบัญชีที่ตั้งไว้ใน
`DASHBOARD_OWNER` เท่านั้น แอดมินคนอื่นไม่เห็นแท็บ และถ้ายิง API ตรง ๆ จะได้ 404

## ทำไมต้องมี agent แยก

`discord-bot.service` ตั้ง `NoNewPrivileges=true` และ `ProtectHome=tmpfs` ไว้ แปลว่า
dashboard **เรียก sudo ไม่ได้** และ **มองไม่เห็นโฟลเดอร์เกม** (ตรวจแล้วทั้งสองอย่าง)

ทางเลือกคือปลดเกราะพวกนั้นออก ซึ่งจะทำให้ช่องโหว่ในบอทลามไปถึง `~/.ssh` และ sudo ได้
เลยแยกเป็น `beammp-agent.service` ตัวเล็กที่เห็นเฉพาะ `/home/flick/beammp-server`
แล้วให้คุยกันผ่าน `127.0.0.1:3101` โดยมีโทเคนกำกับ

```
เบราว์เซอร์ ──HTTPS──> Cloudflare ──> dashboard ──127.0.0.1──> agent ──> BeamMP-Server
                                      (ด่าน owner)              (โทเคน)     (LAN :30814)
```

## ครั้งแรก: ใส่ AuthKey

เซิร์ฟเวอร์รันไม่ได้ถ้าไม่มี AuthKey **แม้จะเล่นกันแค่ใน LAN**

1. เข้า https://keymaster.beammp.com/ ล็อกอินแล้วกด **Create Key**
2. บนเครื่อง: `nano ~/beammp-server/ServerConfig.toml`
3. หาบรรทัด `AuthKey = ""` แล้ววางคีย์ลงในเครื่องหมายคำพูด
4. กลับไปที่หน้าเว็บแล้วกด **เปิดเซิร์ฟเวอร์**

> AuthKey แก้จากหน้าเว็บไม่ได้โดยตั้งใจ และไม่ถูกส่งออกไปฝั่งเว็บเลย — เป็นคีย์ลับ
> ถ้าหลุด คนอื่นเอาไปรันเซิร์ฟในชื่อบัญชีเราได้

## การเข้าเล่น (LAN เท่านั้น)

ไม่ได้ forward พอร์ตที่เราเตอร์ ตามที่ตกลงไว้ คนเล่นต้องอยู่วงเดียวกัน:

- **ในบ้าน (Wi-Fi เดียวกัน)** — Direct Connect ไปที่ `192.168.1.130:30814`
- **ผ่าน Tailscale** — `100.68.119.5:30814` (เซิร์ฟผูก `IP = "::"` จึงรับทุกเน็ตเวิร์ก)

ตรวจแล้วว่า BeamMP **ไม่มี UPnP** — จะไม่แอบเปิดพอร์ตที่เราเตอร์ให้เอง

## ผู้เล่นออนไลน์มาจากไหน

ปลั๊กอิน Lua ที่ `Resources/Server/UndawnStatus/main.lua` เรียก `MP.GetPlayers()`
แล้วเขียนลง `status.json` ทุก 2 วินาที dashboard อ่านไฟล์นั้น

ไม่อ่านจาก log เพราะบรรทัดที่บอกว่าใครเข้า/ออกส่วนใหญ่เป็นระดับ `debug` ซึ่งปิดอยู่
ตามค่าเริ่มต้น ส่วนบรรทัดระดับ `info` เป็นรูปแบบ `<ชื่อ> : Connected` ที่จับผิดตัวได้
ถ้าชื่อผู้เล่นมีอักขระคล้ายกัน

ถ้าลบปลั๊กอินนี้ทิ้ง หน้าเว็บจะขึ้นป้าย **ข้อมูลค้าง** แทนที่จะโชว์ 0 คนให้เข้าใจผิด

## คำสั่งใน Discord

| คำสั่ง | ทำอะไร | ใครเห็น |
|---|---|---|
| `/beamng` | สถานะ + IP + แผนที่ + รายชื่อคนที่กำลังเล่น | ทุกคนในห้องเห็น |
| `/beamng-ip` | เอาแค่ที่อยู่ ไว้ก็อปเร็ว ๆ | คนกดเห็นคนเดียว |

โชว์ IP ในดิสคอร์ดได้เพราะที่อยู่พวกนี้เป็น IP ในวง LAN กับ Tailscale ซึ่งคนนอกวง
เอาไปใช้ไม่ได้ และพอร์ตเกมไม่ได้ forward ออกเน็ต (ตรวจจากเครื่องนอกประเทศแล้วเข้าไม่ถึง)
**ถ้าวันหนึ่งเปลี่ยนไปเปิดพอร์ตจริง ต้องกลับมาคิดเรื่องนี้ใหม่**

IP ไม่ได้ฮาร์ดโค้ดไว้ — อ่านจาก network interface ตอนถาม เพราะ IP ในวง LAN
มาจาก DHCP ของเราเตอร์ เปลี่ยนได้ทุกครั้งที่ไฟดับหรือเราเตอร์รีบูต

## ม็อดและแผนที่

อัปโหลดได้สูงสุด **1GB ต่อไฟล์**

### ทางเข้าสองทาง

| ทาง | ใช้เมื่อไหร่ |
|---|---|
| `https://flick.tail538d1b.ts.net` | เครื่องที่ลง Tailscale — **ใช้ทางนี้เวลาอัปม็อดใหญ่** วิ่งตรงในวง LAN ไม่ผ่านอินเทอร์เน็ต |
| `https://bot.admindawn.top` | ทุกที่ ทุกเครื่อง — สำหรับแอดมินที่ไม่มี Tailscale |

ทั้งสองทางชี้ไปที่ `127.0.0.1:3000` เหมือนกัน พอร์ตยังไม่ได้เปิดออกเน็ต

ทาง Tailscale ใช้ใบรับรอง Let's Encrypt ที่ Tailscale ออกให้ (ต้องเปิด **HTTPS Certificates**
ในหน้า admin ก่อน) จึงเป็น https จริง — จำเป็นเพราะ cookie ตั้ง `Secure` ไว้ จะไม่ถูกส่งบน http ธรรมดา

ผลข้างเคียงที่ควรรู้: ชื่อเครื่องจะไปโผล่ใน Certificate Transparency log ซึ่งเป็นสาธารณะ
คนเห็นชื่อได้แต่เข้าไม่ได้ (ต้องอยู่ใน tailnet)

### ทำไมต้องซอยไฟล์เป็นก้อน

เว็บวิ่งผ่าน Cloudflare Tunnel ซึ่ง**แผนฟรีตัด body ที่ 100 MiB ต่อคำขอ**
วัดขอบเขตมาแล้ว: 104,857,600 bytes ขึ้นไปได้ `413` จากขอบของ Cloudflare
พร้อม header `server: cloudflare` — ก้อนไม่เคยมาถึงเครื่องเราด้วยซ้ำ
(ยิงไฟล์เล็กที่ path เดียวกันโดยไม่ล็อกอินได้ `401` จากแอปเรา = พิสูจน์ว่าคนละคนตี)

เพดานนี้แก้ที่โค้ดฝั่งเราไม่ได้เลย ไม่ว่าจะสตรีมเก่งแค่ไหน ทางเดียวคือทำให้แต่ละคำขอเล็กลง
หน้าเว็บจึงซอยไฟล์เป็นก้อนละ **48MB** แล้วส่งเรียงกัน:

```
POST /api/beammp/mods/begin   {name}          -> {id, chunkBytes}
PUT  /api/beammp/mods/chunk?id=&offset=       (body ดิบของก้อนนั้น)
POST /api/beammp/mods/finish  {id}            -> ตรวจ zip + ย้ายเป็นชื่อจริง
POST /api/beammp/mods/abort   {id}            -> ทิ้งของค้าง
```

**บังคับส่งเรียงลำดับ** (`offset` ต้องเท่ากับจำนวนไบต์ที่รับไปแล้วเป๊ะ) เพราะการต่อไฟล์
ใช้วิธีเขียนต่อท้าย ถ้ายอมให้ก้อนสลับลำดับจะต้องจัดการรูโหว่กลางไฟล์เอง ซึ่งพลาดแล้ว
จะได้ zip ที่ขนาดดูถูกแต่ข้างในพัง — ไปโผล่เป็น "ผู้เล่นโหลดม็อดไม่ได้" ทีหลังโดยหาต้นเหตุยาก

ไฟล์ชั่วคราวตั้งชื่อจาก id ที่สุ่มมา ไม่ใช่ชื่อไฟล์ผู้ใช้ — สองคนอัปชื่อเดียวกันพร้อมกัน
จึงไม่เขียนทับกัน

ทดสอบจริงผ่าน Cloudflare ด้วยไฟล์ 239MB (5 ก้อน, 26 วินาที) แล้วเทียบ sha256
กับต้นฉบับ **ตรงกันทุกไบต์** และ `unzip -t` ผ่าน

เวลาอัปม็อดเสร็จ ระบบจะอ่านสารบัญของไฟล์ zip (ด้วย `zipinfo` ไม่ได้แตกไฟล์)
หาว่ามีแผนที่อะไรอยู่ข้างใน แล้วเอามาใส่ในตัวเลือกแผนที่ให้เลย ไม่ต้องพิมพ์ path เอง

ถ้าม็อดซ่อนแผนที่ไว้ใน zip ซ้อน zip อีกชั้น การสแกนจะมองไม่เห็น — เลือก **"พิมพ์เอง…"**
ในช่องแผนที่แล้วใส่ `/levels/<ชื่อโฟลเดอร์>/info.json` ตรง ๆ ได้

## คำสั่งที่ใช้บ่อย

```bash
systemctl status beammp-agent          # agent ทำงานอยู่ไหม
journalctl -u beammp-agent -f          # log ของ agent (ไม่ใช่ของเซิร์ฟเกม)
nano ~/beammp-server/ServerConfig.toml # แก้ค่าที่หน้าเว็บแก้ไม่ได้ เช่น Port, AuthKey
```

log ของ**ตัวเซิร์ฟเกม**ดูที่แท็บคอนโซลในหน้าเว็บ (สตรีมสดจาก stdout ของโปรเซส)

## ค่าที่แก้จากหน้าเว็บได้

ชื่อเซิร์ฟ, คำอธิบาย, แผนที่, ผู้เล่นสูงสุด, รถต่อคน, แท็ก, และสวิตช์อีก 4 ตัว

ค่าอื่น (`Port`, `IP`, `AuthKey`, `ResourceFolder`) ต้องแก้ในไฟล์เอง — จงใจไม่เปิด
เพราะแก้ผิดแล้วเซิร์ฟขึ้นไม่ได้ และ dashboard ก็ช่วยอะไรไม่ได้ถ้าตัวเองแก้ค่าจนพัง

การแก้ค่าใช้วิธี**แทนที่ทีละบรรทัด** ไม่ได้ generate ไฟล์ใหม่ คอมเมนต์ของ BeamMP
และคีย์ที่เวอร์ชันใหม่เพิ่มมาจึงไม่หายไป
